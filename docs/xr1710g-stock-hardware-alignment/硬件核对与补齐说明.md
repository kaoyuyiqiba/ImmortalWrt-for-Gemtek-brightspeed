# XR1710G 量产固件硬件核对与补齐说明

日期：2026-11-11。当前代码基线为 B17 `e553ff6189cccdada2b572d451f02c251dd6ffb7`，Linux 6.18.60、mt76 `2026.10.28~0936617d`。本次在独立分支 `xr1710g-stock-hardware-alignment` 修改；原构建目录未变，没有连接路由器或烧录。

**本轮补齐有二进制证据的主 PCIe 校准/装载流程，并修正已有 ADC 补丁的结构布局错误及风扇脚本的设备识别/异常处理。没有把“全部硬件已完全还原”或“Wi-Fi 消失已实机解决”作为结论。**

## 参考对象

- 量产 XR1710G 5.1.1.12：[固定提交中的原厂镜像](https://github.com/akorshun/xr1710g-backup-and-flash/blob/1da28af0821a53e64e36c19381c178ae9d5ce39d/firmware/xr1710g-stock-5.1.1.12-tclinux.bin)。容器 SHA256 `4b3a3191007bb197061445cf605a6fd528100ab5c5b6b25d53b9d900408cc83f`；解压内核 SHA256 `4b74cbb519a6eedf229b43c9c8bb7fbca2c56a1620cf9a8fdedbe364345f291e`。
- 内核反汇编为该二进制的文件偏移地址，不冒充厂商源码。工程机备份仅作辅助，不复制工程 EEPROM 或分区到实体机。
- 当前 mt76 的分配约定：`mac80211.c:mt76_alloc_device()`、`mt7996/mmio.c:mt7996_mmio_probe()` 和 `mt7996.h` 中标记 `must be first` 的公共 union。
- 风扇依据：量产 `/usr/bin/gcontrol.sh`、`fan_manager` 配置、当前 Linux `drivers/hwmon/nct7802.c`。LuCI feed 核对版本 `9263b4a64c5a76e51e9cafc88b5df432feec5ed4`（`naoki66/luci-app-airoha`）。
- 已有有线 SerDes 修复参考 [OpenWrt 46d81ac28caf2e0018089da921e9ae953f6dd3d2](https://github.com/openwrt/openwrt/commit/46d81ac28caf2e0018089da921e9ae953f6dd3d2)；本轮保留当前更新的 RTL826x 固件，未以旧量产表替换。

## 实际修改

### 1. 主 PCIe：量产 RX 校准、结果装载和双 lane 发送使能

新增 `929-06-phy-airoha-opt-in-retail-xr1710g-rx-kflow.patch`，两个 XR1710G DTS 的 `&pciephy` 增加 `gemtek,xr1710g-retail-rx-kflow`，binding 同步声明。仅这两个板级配置启用新流程；不改变 PCIe 主链路 Gen3 x2、辅助 Gen2 x1、PLL/SSC 参数及现有 host 复位顺序。

| 补齐内容 | 量产反汇编依据 | 作用 |
| --- | --- | --- |
| 最终锁定固定测量 10 次；频差/锁定位分开读取 | `Rx_PR_Fw_Pre_Cal` 0x369cd0–0x369d58 | 与量产观察窗口一致，不在首次锁定就提前结束；未锁次数汇总告警 |
| 校准退出 LPF R force 保持有效，释放 C override | 0x369d80–0x369db8 | 保留 PMA+0x820 bit16/24；原实现清除了 bit24 |
| Gen2 IDAC 额外写 PMA+0x174[10:0] | 0x369df4–0x369e18 | 补齐另一处校准结果写回，继续保留 reserve 字段 |
| 两 lane PMA+0x19c bit0 开启，清 +0x8c0 bit16 | x2 K-flow 0x36c440–0x36c4dc | 进入量产校准装载流程 |
| 四次校准后 +0x8c0 bit20 低/等待10µs/高 | 0x36c4e0–0x36c670 | 在 CDR power cycle 之前装载新结果 |
| CDR 低/高间10µs，之后等待100µs | 0x36c250–0x36c30c | 对齐量产脉冲，保留当前额外30ms稳定等待 |
| CSR+0xec bit0 TX1_MULTLANE_EN=1 | 0x369ff4–0x36a000、0x36c020–0x36c034、0x36c428–0x36c43c | 量产接口选择2=0、3=0时置位；当前固定清零。probe 0x36f9dc–0x36fa4c 与 SCU PCIC=2 分支交叉确认 |

这是有明确静态差异的修复候选。它有助于缩小 PCIe 训练/校准差异，但不能单独证明此前 MT7996 超时、CmpltTO 的唯一根因。

### 2. 已有 ADC 补丁：修复公共结构偏移

新增 `136-mt7996-preserve-leading-mt76-union-for-adc.patch`，在现有135补丁之后应用。135补丁把 `thermal_adc_debug` 放在公共 union 前面，但 `mt76_alloc_device()` 直接把 `hw->priv` 当 `mt76_dev` 初始化，后续 `container_of(mdev, struct mt7996_dev, mt76)` 要求偏移0。新增前置字段会使转换指向分配区之前，存在越界/内存破坏风险。

将诊断字段移到 union 后，保留 ADC 查询接口、缓存、恢复期退避。增加 `offsetof(mt7996_dev, mt76/mphy)==0` 两个静态断言。交叉编译已复现：原版本两个断言失败，修正版通过。这是本轮发现的确定代码错误；不据此倒推所有历史固件都含相同二进制，运行版本仍应以构建哈希确认。

### 3. 风扇配置异常处理

修正板级 `airoha_fan`；通过仓库标准 `patches/feeds/app_airoha/` 机制修正 LuCI 的 `/etc/init.d/fan`：

- 去掉找不到 NCT7802 时盲写 `hwmon5` 的回退，每次应用时按 `name=nct7802` 重新查找。
- 调整配置期间先请求手动255 PWM；检查每次写入结果，失败尝试回到手动255并记录错误。
- LuCI 脚本在写表前校验温度递增、PWM不递减、合法范围、预设名及手动值；拒绝前导零等有歧义的输入。
- 保留当前 OpenWrt PWM 曲线；删去“等同原厂”的错误注释。

原厂以 local/PHY/rai0 分别配置阈值和 RPM，并向可编程温源写入温度；当前 hwmon 通道编号、PWM表、原厂RPM表并非同一接口。不能直接把原厂 1300/1700/2300/2900 RPM 当 PWM，或把 fault 的128℃当有效无线温度。本轮没有声称已移植原厂完整多温源风扇管理；控制器写入本身失败时，软件也不能保证风扇物理上达到全速。

## 验证结果

- 实际修补后的 PCIe PHY 源码通过 ARM64 Kbuild W=1 交叉编译。
- mt76/mt76-connac-lib/mt7996e **包含NPU** 在隔离副本重新编译、MODPOST和链接成功，产出`.ko`。存在三个已有 `MODULE_DESCRIPTION` 元数据告警；不是整固件全构建。
- 两个XR1710G DTB编译成功；分别12/11项原有dtc告警，按告警类型/节点/内容与基线对比未新增；未进行完整dt-schema验证。
- 从真实修补驱动提取函数，fake-MMIO + UBSan执行 opt-in开/关、锁成功/全不锁四组；校准顺序、IDAC第7档、采样次数、LPF退出、0x174、latch先于CDR、双lane发送、RX detect/AEQ检查通过。
- 原厂受限AArch64解释器与真实C的主初始化轨迹对比，seed=0与0xa5a5a5a5各132个最终寄存器一致；未启用opt-in的完整模拟轨迹与基线一致。
- 风扇13组模拟行为通过：换hwmon编号、设备缺失、曲线非法、手动值非法、写入失败、正常自动/手动等。
- 所有新kernel/mt76/feed补丁零fuzz应用检查；正反向仓库补丁将在打包时对固定基线树验证。

### 验证边界

受限解释器只实现此函数用到的指令，stub掉硬件readback、delay、SerDes查询、校准函数调用；比较的是选定主初始化路径的写寄存器最终值，不能证明瞬态波形/动态硬件状态一致。校准用真实C另行模拟，最终锁定位在模拟中固定；未核对量产后续诊断重试的完整硬件行为。其它开源等待时间通常更长，保留现有延时，不声称逐笔写时序完全相同。未实机测试、未整固件构建，不能把本报告作为新版本Wi-Fi稳定性验收。

## 编译与实机验收方法

1. 在固定B17基线上应用仓库补丁，更新/安装feeds后运行 `scripts/apply-feed-patches.sh`；feed补丁应由现有构建钩子应用，不手改build_dir。换feed版本必须重新检查应用。
2. 保留原`.config`、feeds提交、源HEAD和已知可用固件；正常make defconfig后重编kernel、mt76及固件。**不能只换一个旧`.ko`**：结构布局改变要求mt7996各对象同批重建。
3. 新固件刷入后先确认主 `LnkSta 8GT/s Width x2`、辅助 `5GT/s Width x1`，无线三band、eeprom实际来源/哈希、NPU固件、PHY地址及链路、温度标签/fault、风扇转速。
4. 冷启动/软重启分别重复验收；随后2.4/5/6GHz各做不限速单向、反向和双向长测。优先无线到独立有线iperf3服务器；路由器本地iperf只能验证部分路径。记录每方向Mbps、丢包/重传/掉线次数，日志限额保存。
5. 同时抓MCU超时、PCIe AER/CmpltTO、LTSSM/link、SER/NPU与客户端断开时间轴；温控查询维持5秒或更低频率，避免并发raw查询。出现严重故障先保全日志，不直接归因为某个补丁。

## 回退

原构建树保持原样。本分支改动按PCIe、ADC布局、风扇三个独立提交保存，使用中文提交说明。可在干净树用导出的 `reverse.patch` 回到B17，或依次revert对应提交。回退涉及驱动布局时同样完整重建相关模块；实体机保留原固件恢复路径，不恢复工程mtd备份。

证据日志与脚本位于本目录和本机 `F:\openwrt\research\stock-hardware-alignment-20261111`。报告未携带账号、私钥或个体EEPROM内容。
